# Attention-CNN-LSTM Intrusion Detection System

Deep-learning-based Network Intrusion Detection System (IDS) trained on **CIC-IDS2017**.
Compares four architectures and ships a live Streamlit dashboard with real-time packet classification.

## Models and Architecture

All four models receive **78 numerical flow features** extracted from CIC-IDS2017,
normalised with `StandardScaler`, and output a single binary logit
(BENIGN=0 / ATTACK=1) via `BCEWithLogitsLoss`.

### 1. CNN Baseline
```
Input (78) → Conv1D(64, k=3) + BN + ReLU + MaxPool
           → Conv1D(128, k=3) + BN + ReLU
           → Flatten → Dense → logit
```
Fast feature extractor; no temporal modelling.

### 2. LSTM Baseline
```
Input (78) → treats features as a 1-D sequence
           → LSTM(64 hidden) → last hidden state → Dense → logit
```
Models sequential dependencies across the 78 features.

### 3. CNN-LSTM
```
Input (78) → Conv1D(64) + Pool → Conv1D(128)
           → LSTM(64) on CNN feature maps → Dense → logit
```
CNN extracts local patterns; LSTM captures their sequence relationships.

### 4. Attention-CNN-LSTM ⭐
```
Input (78) → Conv1D(64) + Pool → Conv1D(128)
           → LSTM(64) → all hidden states
           → Self-attention (scaled-dot-product) over LSTM outputs
           → Weighted sum → Dropout(0.3) → Dense → logit
```
The self-attention gate lets the model weight which parts of the sequence
matter most for each sample — enabling it to focus on the most discriminating features.

## Training Pipeline

```
CIC-IDS2017 CSVs  →  preprocess_cicids2017.py
                       ├── loads 8 CSVs, strips whitespace, drops NaN/Inf
                       ├── binary-encodes Label (BENIGN=0, ATTACK=1)
                       ├── fits StandardScaler on 80% train split
                       └── saves X_train.npy, X_test.npy, y_*.npy, scaler.pkl

X_train, y_train  →  run_training.py
                       ├── DataLoader (batch=256, num_workers=0)
                       ├── Adam + OneCycleLR scheduler
                       ├── trains each model for N epochs
                       ├── evaluates on X_test (Accuracy, F1, MCC)
                       └── saves checkpoints to experiments/checkpoints/
```

## Live Dashboard

### Traffic Sources

| Mode | Description |
|---|---|
| **Simulated** | Draws real CIC-IDS2017 test-set flow vectors (inverse-transform → raw → re-scale in classify()) |
| **Real Device** | Reads flows captured by `capture_agent.py` from your NIC |
| **Mixed** | Both simultaneously |

### Inference Pipeline (per sample)

```
feature vector (raw)
  → model_loader.IDS_Model.classify()
      ├── StandardScaler.transform()   ← scale to z-scores
      ├── PyTorch model.forward()      ← compute logit
      ├── sigmoid(logit) → prob        ← attack probability
      └── prob >= threshold → ATTACK / BENIGN
```

### Detection Threshold

The threshold is **auto-tuned at model load** using 2 000 stratified test-set samples to
maximise F1-score. You can adjust it manually in the sidebar. Use **🎯 Auto-tune** to recompute.


Then set **Traffic Source → Real Device** (or Mixed) on the dashboard and press ▶ Start.

### How real attack detection works

The capture agent labels all live flows as `true_label=0` (BENIGN) because it cannot
know the ground truth in advance. The model then classifies each flow independently.

## Confusion Matrix — What TP, TN, FP, FN Mean

For a binary classifier (BENIGN / ATTACK), a **confusion matrix** compares what the
model predicts against what the traffic actually is.

```
                  Predicted
                 BENIGN    ATTACK
Actual  BENIGN │  TN  │  FP  │
        ATTACK │  FN  │  TP  │
```

| Term | Full Name | In this IDS | Ideal |
|---|---|---|---|
| **TP** | True Positive | Traffic that **IS** an attack, and the model **correctly flags it** as ATTACK | High |
| **TN** | True Negative | Traffic that **is NOT** an attack, and the model **correctly clears it** as BENIGN | High |
| **FP** | False Positive | Normal traffic that the model **wrongly flags** as ATTACK (false alarm) | Low |
| **FN** | False Negative | A real attack the model **misses** and labels as BENIGN (missed detection) | Low — most dangerous |

### Derived metrics

| Metric | Formula | What it measures |
|---|---|---|
| **Accuracy** | (TP + TN) / Total | Overall correctness |
| **Precision** | TP / (TP + FP) | Of all flagged attacks, how many were real? |
| **Recall** | TP / (TP + FN) | Of all real attacks, how many were caught? |
| **F1** | 2 × (Precision × Recall) / (Precision + Recall) | Harmonic mean — balances precision and recall |
| **MCC** | Matthews Correlation Coefficient | Balanced metric robust to class imbalance |

> In a real-world IDS, **Recall (detection rate) is the most critical metric**.  
> A missed attack (FN) is far more dangerous than a false alarm (FP).

### Reading the dashboard in Real Device mode

In Real Device mode, the capture agent sets `true_label=BENIGN` for every flow
(as ground truth is unknown). This means:

| Dashboard shows | Real-world interpretation |
|---|---|
| TN ✓ | Normal traffic correctly identified — safe |
| **FP** ⚠️ | Could be a **real attack being detected** — investigate the Source IP and Port |
| FN | Not possible in Real Device mode (all true labels are BENIGN) |

## Testing with Kali Linux Attack Tools

Run the dashboard in **Real Device** or **Mixed** mode (against your own lab machine —
never against systems you don't own). Open Kali Linux on the same LAN segment and
run the commands below. Each one maps to an attack profile the model was trained on.

> ⚠️ **Legal reminder**: Only run penetration tests against machines you own or have
> explicit written permission to test. These commands are for educational lab use only.

---

### 1. Port Scan → PortScan detection

Maps to: high Fwd Packets/s, 1-packet flows, SYN + RST flags, zero payload.

```bash
# SYN scan (stealth) — most similar to the training data
sudo nmap -sS -T4 <target-ip>

# Full TCP connect scan
nmap -sT -p 1-65535 <target-ip>

# Aggressive scan (OS detection + version)
nmap -A <target-ip>
```
**Expected dashboard result**: Multiple ATTACK alerts, Source IP = Kali IP, Port = varying.

---

### 2. DDoS / DoS → DDoS detection

Maps to: extremely high Flow Bytes/s, near-zero IAT, zero backward traffic.

```bash
# SYN flood using hping3 (install: sudo apt install hping3)
sudo hping3 -S --flood -V -p 80 <target-ip>

# UDP flood
sudo hping3 --udp -p 53 --flood <target-ip>

# ICMP flood (ping flood)
sudo hping3 -1 --flood <target-ip>
```
**Expected dashboard result**: Repeated ATTACK flags at very high confidence, low P(Atk) Std.

---

### 3. Brute Force → BruteForce detection

Maps to: port 22, many bidirectional flows, repeated SYN, regular IAT.

```bash
# SSH brute force with Hydra (install: sudo apt install hydra)
hydra -l root -P /usr/share/wordlists/rockyou.txt ssh://<target-ip>

# FTP brute force
hydra -l admin -P /usr/share/wordlists/rockyou.txt ftp://<target-ip>

# Medusa alternative
medusa -h <target-ip> -u root -P /usr/share/wordlists/rockyou.txt -M ssh
```
**Expected dashboard result**: ATTACK alerts on port 22, high ACK flag count, bidirectional flows.

## Debugging Guide

### ModuleNotFoundError: No module named 'src'
`src/` lives inside `training/`. The `pyrightconfig.json` tells your IDE, and
`model_loader.py` adds it to `sys.path` at runtime. Always run from the **project root**:
```bash
# ✅ Correct
streamlit run app/dashboard.py

# ❌ Wrong — relative imports break
cd app && streamlit run dashboard.py
```

### Scaler NOT FOUND in capture_agent
```bash
# Confirm you are running from project root
pwd                    # must end in: attention_cnn_lstm_ids
ls data/processed/     # must contain scaler.pkl

# Capture agent needs sudo → venv python explicitly
sudo .venv/bin/python app/capture_agent.py --interface <iface>
```

### Dashboard shows all FN (False Negatives)
Caused by the threshold being too high for the model's output probabilities.
Click **🎯 Auto-tune** and then **Apply**, or restart the dashboard
(auto-tune runs automatically at model load).

### Low accuracy in session metrics
Check:
1. **Simulated attack %** — set to 20–30%, not 0% or 100%
2. **Traffic source** — "Simulated" or "Mixed" for a mix of benign + attack
3. **Threshold** — auto-tune should set this correctly at model load

### Streamlit sklearn UserWarning (feature names)
This is a cosmetic warning — the scaler scales by position, not column name.
It is suppressed in `model_loader.py`. No action needed.

### nfstream not found (capture agent)
```bash
pip install nfstream
# Note: nfstream requires libpcap on Linux
sudo apt install libpcap-dev     # Debian/Ubuntu
```
